## Лабораторная работа 3: Формы и локальное состояние приложения

**Дата выполнения:** 28 сентября 2026 г.  

### 1. Результат лабораторной работы 3

1. **Поднятие общего состояния (State Lifting):**
   - Список задач перенесен в состояние `useState` корневого компонента `App.tsx`.
   - Исходный массив из `src/data/tasks.ts` используется исключительно для инициализации начального состояния.
   - Прямой импорт данных удален из страниц `TasksPage` и `TaskDetailsPage`; данные и колбэки передаются через типизированные `props`.

2. **Неизменяемые операции CRUD:**
   - `createTask(draft: TaskDraft): string` — добавление задачи с копированием спредом `[...current, { ...draft, id }]` и генерацией уникального ID через `crypto.randomUUID()`.
   - `updateTask(id: string, draft: TaskDraft): void` — обновление записи методом `current.map()`.
   - `deleteTask(id: string): void` — удаление записи методом `current.filter()`.
   - Все функции обновления состояния остаются чистыми (без побочных эффектов внутри сеттеров).

3. **Единая переиспользуемая форма (`TaskForm`):**
   - Компонент `src/components/TaskForm.tsx` обслуживает как создание (`NewTaskPage`), так и редактирование (`EditTaskPage`).
   - Форма изолированно хранит черновик в локальном состоянии `draft`. Нажатие «Отмена» не затрагивает исходный объект в общем списке.
   - Использован ключ `key={task.id}` при редактировании для гарантированного сброса черновика при переключении между задачами.
   - Кнопки формы строго типизированы: `type="submit"` для отправки и `type="button"` для отмены.

4. **Валидация и предметная проверка:**
   - Обязательное название (от 3 до 100 символов после `trim()`).
   - Обязательный срок сдачи (дедлайн).
   - **Предметное правило:** если задача завершена (`status === 'done'`), поле описания обязательно должно содержать результат выполнения.
   - Форма использует `noValidate`, ошибки выводятся в доступном блоке с `role="alert"`, введенный черновик не стирается при ошибке.

5. **Удаление с подтверждением:**
   - На странице `TaskDetailsPage` добавлена кнопка «Удалить» с модальным подтверждением `window.confirm`.
   - После подтверждения задача удаляется, а пользователь возвращается на `/tasks` с параметром `{ replace: true }`.

6. **Локальная фильтрация:**
   - В `TasksPage` внедрен фильтр по статусу (`useState<TaskStatus | 'all'>('all')`).
   - Добавлены селектор и кнопка «Сбросить фильтр».
   - Корректно разделены пустые состояния: «Задач вообще нет» и «Нет задач с выбранным статусом».

7. **Информационное уведомление о сеансе:**
   - В `AppLayout` добавлена визуальная плашка о том, что изменения хранятся в оперативной памяти до перезагрузки вкладки.
