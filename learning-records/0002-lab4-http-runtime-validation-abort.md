# Асинхронная загрузка данных, Runtime-валидация и AbortController

Освоен переход от статических данных к работе с внешними ресурсами по протоколу HTTP (Fetch API), механизм отмены запросов через `AbortController` и разница между compile-time типизацией TypeScript и runtime-проверкой данных во время выполнения.

## Evidence
- Реализован HTTP-сервис `src/services/tags.ts`, запрашивающий `/demo/tags.json` с заголовком `cache: 'no-store'` и проверяющий `response.ok`.
- Внедрен пользовательский предикат типа `isTag(value: unknown): value is Tag` и разбор массива `parseTags`, предотвращающие падение приложения при некорректной структуре JSON.
- В кастомном хуке `src/hooks/useTags.ts` реализована очистка эффекта с `controller.abort()` и флагом `active = false`, устраняющая гонки состояний и попытки обновления стейта размонтированного компонента.
- Проверена устойчивость формы: при имитации сбоя сети (Offline) черновик `draft` сохраняется, а функция `retry()` перезапрашивает справочник без перезагрузки вкладки.

## Implications
- Следующий этап (ЛР 5+) предусматривает замену локального статического источника `/demo/tags.json` на облачную базу данных PostgreSQL (Supabase) и вынесение мутаций данных на серверный API.
- Шаблон изоляции сетевого хука (`useTags`) и строгой runtime-валидации масштабируется на все сущности StudyFlow (задачи, курсы, дедлайны).
