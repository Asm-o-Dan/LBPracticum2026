Асинхронный Fetch, Runtime Type Guard и AbortController

Как безопасно загружать справочники по HTTP и не ронять React-приложение

1. Главное противоречие: TypeScript vs Браузер

Когда вы пишете const tags = (await res.json()) as Tag[], вы совершаете опасную ошибку. Компилятор TypeScript существует только во время сборки. В браузере работает обычный JavaScript, который понятия не имеет о типах Tag. Если сервер пришлет ошибку 404, HTML или число вместо строки, программа упадет в белый экран (Uncaught TypeError).

Золотое правило надежности: Данные, приходящие из внешнего мира (сеть, файлы, ввод пользователя), всегда типизируются как unknown и проверяются во время выполнения через функции-предикаты (Type Guards).
// Предикат типа (User-Defined Type Guard): function isTag(value: unknown): value is Tag { if (typeof value !== 'object' || value === null) return false; return ( 'id' in value && typeof value.id === 'string' && 'name' in value && typeof value.name === 'string' ); }

2. Жизненный цикл и AbortController

Что произойдет, если пользователь на медленном 3G-интернете откроет форму создания задачи, передумает и через 0.2 секунды нажмет «Назад»?

  • Компонент TaskForm размонтируется и удалится из памяти DOM.
  • Асинхронный промис fetch() продолжит лететь по проводам.
  • Когда ответ наконец вернется, обработчик попытается вызвать setLoad() у мертвого компонента.

Чтобы этого избежать, функция очистки useEffect отменяет запрос:

useEffect(() => { const controller = new AbortController(); let active = true; getTags(controller.signal) .then((data) => { if (active) setLoad({ status: 'success', data }); }) .catch((err) => { if (active) setLoad({ status: 'error', message: err.message }); }); return () => { active = false; // Блокируем вызов сеттера controller.abort(); // Физически отменяем HTTP-запрос }; }, [attempt]);

3. Проверка усвоения (Retrieval Practice)

Почему после fetch() проверка `if (!response.ok)` строго обязательна?
Потому что fetch возвращает HTML, а не строку JSON.
Потому что fetch не отклоняет промис при статусах 404 и 500.
Потому что без этого Vite заблокирует запросы через CORS.
