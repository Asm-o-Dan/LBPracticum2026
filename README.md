## 1. Описание и основной сценарий

**StudyFlow** помогает студенту отслеживать семестровые курсы, дедлайны по лабораторным работам и статус выполнения практических заданий. Пользователь просматривает список дисциплин, фильтрует задачи по статусу, открывает карточку конкретного задания, создает новые записи через форму, редактирует поля или удаляет задачи с подтверждением.

## 2. Стек технологий

- **Фронтенд-библиотека:** React 19

- **Язык программирования:** TypeScript 5.8+ (строгий режим `strict: true`)

- **Среда выполнения:** Node.js `22.23.0` (зафиксирована в `.node-version`)
- **Пакетный менеджер:** npm `10.9.8`
- **Контроль версий:** Git

## 3. Адреса страниц и маршрутизация (Лабораторная работа 3)

В приложении настроена клиентская маршрутизация без перезагрузки страницы (SPA):

| Маршрут | Описание экрана | Компонент |
|---|---|---|
| `/` | Перенаправление (редирект через `<Navigate to="/tasks" replace />`) | `App.tsx` |
| `/tasks` | Список задач с карточками и локальным фильтром по статусу | `TasksPage` |
| `/tasks/:id` | Страница подробностей задачи, кнопками редактирования и удаления | `TaskDetailsPage` |
| `/tasks/new` | Экран создания задачи с валидацией через `TaskForm` | `NewTaskPage` |
| `/tasks/:id/edit` | Экран редактирования задачи через `TaskForm` | `EditTaskPage` |
| `*` (любой другой) | Экран 404 для неизвестных маршрутов (например, `/unknown`) | `NotFoundPage` |

> [!NOTE]  
> **Ограничение хранения данных (сеанс в памяти):** В рамках ЛР 3 все добавленные, измененные или удаленные задачи хранятся исключительно в оперативной памяти открытого приложения (`useState` в корневом компоненте `App`). При перезагрузке страницы (F5) восстанавливается демонстрационный массив из `src/data/tasks.ts`. Постоянное хранилище появится при интеграции с Supabase в последующих работах.

## 4. Инструкция по установке и запуску

### Требования к окружению
- Установленный Node.js версии `22.x` (проверить: `node -v`)
- Git (проверить: `git -v`)

### Запуск в режиме разработки
Из корня проекта:

```bash
cd frontend
npm ci
npm run dev
```

После запуска откройте в браузере локальный адрес (по умолчанию `http://localhost:5173`).

### Проверка сборки и preview

```bash
cd frontend
npm run build
npm run preview
```

Команда `npm run build` выполняет строгую проверку типов TypeScript (`tsc -b`), после чего Vite формирует оптимизированные статические файлы в директории `frontend/dist`. `npm run preview` поднимает локальный HTTP-сервер для проверки собранного SPA-бандла.

## 5. Что работает сейчас (Лабораторная работа 3)

1. **Поднятие состояния в `App.tsx`:** Общий список задач вынесен на верхний уровень (`useState`), что гарантирует синхронизацию данных между списком, подробностями, формой создания и редактирования.
2. **Неизменяемые обновления данных (Immutability):**
   - Добавление задачи через спред массива: `[...current, { ...draft, id }]`.
   - Редактирование через `current.map()`.
   - Удаление через `current.filter()`.
   - Генерация уникальных идентификаторов через встроенный стандарт `crypto.randomUUID()`.
3. **Единая переиспользуемая форма (`TaskForm`):**
   - Используется как для добавления (`NewTaskPage`), так и для редактирования (`EditTaskPage`).
   - Работает через изолированный локальный черновик (`draft`), благодаря чему отмена редактирования не меняет исходную карточку.
   - Сброс состояния формы при переключении между задачами через ключ `key={task.id}`.
4. **Валидация полей и предметная проверка:**
   - Название задачи обязательно (от 3 до 100 символов после `trim()`).
   - Срок сдачи обязателен.
   - **Предметное правило:** завершенная задача (`status === 'done'`) обязана иметь непустое описание результата сдачи.
   - Ошибки валидации выводятся в доступном блоке с `role="alert"`, введенные пользователем данные не сбрасываются.
5. **Удаление с подтверждением:** На странице деталей задачи кнопка «Удалить» вызывает диалог подтверждения `window.confirm`. После удаления выполняется переход на `/tasks` с параметром `{ replace: true }`.
6. **Локальный фильтр по статусу:** В `TasksPage` добавлен селектор («Все», «Запланировано», «В работе», «Готово») и кнопка сброса. Разделены состояния «Задач вообще нет» и «Нет задач с выбранным статусом».
7. **Информационное уведомление:** В `AppLayout` добавлена плашка о том, что изменения сохраняются в рамках текущего сеанса до перезагрузки вкладки.
8. **Качество кода и сборка:** Полная типизация через `Task` и `TaskDraft = Omit<Task, 'id'>`, строгий режим TS, успешный `npm run build` и 0 предупреждений в `oxlint`.

## 6. Текущие ограничения

- Хранение задач является локальным (in-memory) в рамках текущей сессии браузера.
- Полноценная аутентификация студентов и персистентное сохранение в PostgreSQL через Supabase реализуются в ЛР 5+.

## 7. Использование ИИ

- **В чем помог ИИ:** проектирование чистых функций обновления массива без мутаций, разметка стилей формы и панели фильтрации, генерация чек-листа граничных сценариев тестирования.
- **Что проверено самостоятельно:** изоляция локального черновика от глобального состояния при отмене, проверка предметной валидации при статусе `done`, корректность работы `crypto.randomUUID()`, переключение фильтров и чистая компиляция `tsc -b`.
