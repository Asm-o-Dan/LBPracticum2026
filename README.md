## 1. Описание и основной сценарий

**StudyFlow** помогает студенту отслеживать семестровые курсы, дедлайны по лабораторным работам и статус выполнения практических заданий. Пользователь просматривает список дисциплин, видит ближайшие сроки сдачи, открывает подробности конкретного задания, переходит к экрану создания и контролирует учебную нагрузку по семестру.

## 3. Адреса страниц и маршрутизация (Лабораторная работа 2)

В приложении настроена клиентская маршрутизация без перезагрузки страницы (SPA):

| Маршрут | Описание экрана | Компонент |
|---|---|---|
| `/` | Перенаправление (редирект через `<Navigate to="/tasks" replace />`) | `App.tsx` |
| `/tasks` | Список всех учебных задач и дедлайнов с карточками | `TasksPage` |
| `/tasks/:id` | Страница подробностей задачи по идентификатору (например, `/tasks/t1`) | `TaskDetailsPage` |
| `/tasks/new` | Экран создания задачи (заглушка перед ЛР 3) | `NewTaskPage` |
| `*` (любой другой) | Экран 404 для неизвестных маршрутов (например, `/unknown`) | `NotFoundPage` |

> [!NOTE]  
> **Демонстрационные данные:** Все записи в текущей работе являются демонстрационными и хранятся в типизированном массиве `src/data/tasks.ts`. Подключение серверного API и базы данных Supabase запланировано на последующие лабораторные работы.

## 4. Инструкция по установке и запуску

### Требования к окружению
- Установленный Node.js версии `22.x` (проверить: `node -v`)
- Git (проверить: `git -v`)

### Запуск в режиме разработки
Из корня проекта:

```bash
cd frontend
npm ci
npm run dev
```

После запуска откройте в браузере локальный адрес (по умолчанию `http://localhost:5173`).

### Проверка сборки и preview

```bash
cd frontend
npm run build
npm run preview
```

Команда `npm run build` выполняет строгую проверку типов TypeScript (`tsc -b`), после чего Vite формирует оптимизированные статические файлы в директории `frontend/dist`. `npm run preview` поднимает локальный HTTP-сервер для проверки собранного SPA-бандла.

## 5. Что работает сейчас (Лабораторная работа 2)

1. **Единый каркас (Layout):** Создан `AppLayout` с шапкой, мета-информацией студента, навигационными ссылками (`NavLink` с подсветкой активной вкладки через класс `.active`) и контейнером `<Outlet />`.
2. **Клиентская маршрутизация:** Подключен `BrowserRouter`, настроены декларативные маршруты (`Routes`, `Route`, `Navigate`), переходы выполняются мгновенно через `Link`/`NavLink` без перезагрузки HTML-страницы.
3. **Строгая типизация данных:** Описан тип `Task` (8 содержательных полей) со строковыми объединениями для статусов (`todo`, `in_progress`, `done`) и приоритетов (`low`, `medium`, `high`).
4. **Компонент карточки (`TaskCard`):** Принимает типизированный объект `task` через props, выводит понятные русские названия статусов/приоритетов и ссылку на подробности.
5. **Страница списка (`TasksPage`):** Рендерит карточки через `.map()` со стабильным `key={task.id}`, содержит проверку пустого состояния (`empty-state`).
6. **Страница деталей (`TaskDetailsPage`):** Извлекает `:id` через хук `useParams`, находит соответствующую задачу и выводит полные данные.
7. **Обработка граничных ситуаций и ошибок:**
   - Неизвестный маршрут (`/unknown`) отображает страницу 404 (`NotFoundPage`).
   - Несуществующий ID задачи (`/tasks/missing`) корректно отображает экран «Задача не найдена» с ссылкой возврата к списку.
   - Прямое открытие карточки по ссылке и перезагрузка страницы (F5) сохраняют работоспособность интерфейса.
8. **Адаптивная верстка и доступность:** Сетка карточек адаптируется под экраны смартфонов (~360px) и ПК, поддерживается полная навигация с клавиатуры клавишей `Tab` с видимым индикатором `:focus-visible`.
9. **Сборка проекта:** Команда `npm run build` и линтер `oxlint` выполняются без ошибок и предупреждений.
