## 1. Описание и основной сценарий

**StudyFlow** помогает студенту отслеживать семестровые курсы, дедлайны по лабораторным работам и статус выполнения практических заданий. Пользователь просматривает список дисциплин, фильтрует задачи по статусу, открывает карточку конкретного задания, создает новые записи с выбором категории из сетевого справочника тегов, редактирует поля или удаляет задачи с подтверждением.

## 2. Стек технологий

- **Фронтенд-библиотека:** React 19
- **Маршрутизация (SPA):** React Router 8+ (декларативный API)
- **Сетевые запросы и HTTP:** Fetch API, `AbortController`, `cache: 'no-store'`
- **Управление состоянием:** React Hooks (`useState`, `useEffect`, кастомный хук `useTags`)
- **Язык программирования:** TypeScript 5.8+ (строгий режим `strict: true`, runtime type guard `isTag`)
- **Инструмент сборки и dev-сервер:** Vite 6 / Vite 8
- **Среда выполнения:** Node.js `22.23.0` (зафиксирована в `.node-version`)
- **Пакетный менеджер:** npm `10.9.8`
- **Контроль версий:** Git

## 3. Адреса страниц, маршрутизация и сетевой справочник (Лабораторная работа 4)

В приложении настроена клиентская маршрутизация без перезагрузки страницы (SPA):

| Маршрут | Описание экрана | Компонент |
|---|---|---|
| `/` | Перенаправление (редирект через `<Navigate to="/tasks" replace />`) | `App.tsx` |
| `/tasks` | Список задач с карточками и локальным фильтром по статусу | `TasksPage` |
| `/tasks/:id` | Страница подробностей задачи, кнопками редактирования и удаления | `TaskDetailsPage` |
| `/tasks/new` | Экран создания задачи с выбором сетевого тега через `TaskForm` | `NewTaskPage` |
| `/tasks/:id/edit` | Экран редактирования задачи через `TaskForm` | `EditTaskPage` |
| `*` (любой другой) | Экран 404 для неизвестных маршрутов (например, `/unknown`) | `NotFoundPage` |

### Сетевой источник справочника тегов
- **Файл на диске:** `frontend/public/demo/tags.json`
- **HTTP-эндпоинт:** `GET /demo/tags.json` (раздаётся сервером Vite)
- **Формат данных:** массив объектов `Tag[]` с полями `id` (строковый код) и `name` (название):
  - `lab`: Лабораторная
  - `practice`: Практика
  - `seminar`: Семинар
  - `coursework`: Курсовая работа
  - `exam`: Экзамен

> [!NOTE]  
> **Ограничение хранения основных записей:** Основной список задач хранится в оперативной памяти React (`useState` в `App.tsx`) и сбрасывается к демо-набору при перезагрузке страницы (F5). Справочник тегов запрашивается по сети по HTTP при каждом открытии формы. Постоянная база данных появится при интеграции с Supabase в ЛР 5+.

## 4. Инструкция по установке и запуску

### Требования к окружению
- Установленный Node.js версии `22.x` (проверить: `node -v`)
- Git (проверить: `git -v`)

### Запуск в режиме разработки
Из корня проекта:

```bash
cd frontend
npm ci
npm run dev
```

После запуска откройте в браузере локальный адрес (по умолчанию `http://localhost:5173`).

### Проверка сборки и preview

```bash
cd frontend
npm run build
npm run preview
```

Команда `npm run build` выполняет строгую проверку типов TypeScript (`tsc -b`), после чего Vite копирует статические файлы из `public/demo` в `dist/demo` и формирует оптимизированный SPA-бандл. `npm run preview` поднимает локальный сервер для проверки собранного проекта.

## 5. Что работает сейчас (Лабораторная работа 4)

1. **Сетевой справочник по HTTP:**
   - JSON-файл размещён в `public/demo/tags.json` и запрашивается через реальный `GET /demo/tags.json` с проверкой `response.ok`.
   - Запрос виден во вкладке Network браузера и подтверждается заголовками ответа.
2. **Проверка структуры во время выполнения (Runtime Type Guard):**
   - Предикат `isTag(value: unknown): value is Tag` валидирует поля объекта без небезопасного приведения типов `as Tag[]`.
   - Функция `parseTags` проверяет массив на корректность и контролирует уникальность `id` через `Set`.
3. **Отдельный HTTP-сервис (`services/tags.ts`):**
   - Изолирует сетевую логику от интерфейса, использует `cache: 'no-store'` и передает `signal` для отмены запроса.
4. **Пользовательский хук `useTags` (`hooks/useTags.ts`):**
   - Управляет жизненным циклом запроса (`loading`, `error`, `success`).
   - Использует `AbortController` и флаг `active` для предотвращения утечек памяти и обновления состояния размонтированного компонента.
   - Предоставляет функцию `retry()` для повторной попытки без перезагрузки приложения и без потери введённых данных в форме.
5. **Интеграция сетевого селектора в `TaskForm`:**
   - Прежний текстовый ввод тега заменён на выпадающий список `<select>`.
   - Отображаются состояния: индикатор загрузки (`⏳ Загружаем теги…`), сообщение об ошибке с кнопкой `Повторить`, пустое состояние.
   - Если в редактируемой задаче сохранён тег, отсутствующий в справочнике, он отображается в отдельном неактивном `<option>` с предупреждением.
6. **Защита сохранения данных:**
   - Кнопка «Сохранить» заблокирована (`disabled={!canSave}`) до успешного получения справочника и выбора допустимого тега.
   - Обработчик `handleSubmit` дополнительно проверяет `canSave` перед сохранением.
7. **Сохранение возможностей ЛР 3:**
   - Полный CRUD в памяти `App`, чистые обновления без мутаций, фильтрация по статусу, отмена без изменения оригинала.
8. **Качество кода и сборка:**
   - Строгий режим TypeScript (`strict: true`), успешная сборка `npm run build`, 0 предупреждений и 0 ошибок в линтере `oxlint`.

## 6. Текущие ограничения

- Справочник тегов является статическим демонстрационным файлом в каталоге `public/demo/`.
- Основной список задач хранится в оперативной памяти текущего сеанса.
- В ЛР 5+ источник справочника и хранение задач будут переведены на базу данных Supabase.

## 7. Использование ИИ

- **В чем помог ИИ:** проектирование типизированного runtime-валидатора для входящих JSON-данных, настройка отмены сетевых запросов через `AbortController` в хуке `useTags`, адаптация стилей состояний загрузки.
- **Что проверено самостоятельно:** отображение сетевого запроса к `/demo/tags.json` в Network, сохранение черновика при симуляции Offline и последующем retry, отмена сохранения при недоступном теге, чистота сборки `tsc -b` и запуск сервера preview.
